# 选择性阅读原文标记方案

> 修订结论（2026-08-15）：**“选择性阅读”不是从阅读计划反复跳转到原文，而是把原文按原始顺序呈现为一条连续的引导阅读流：值得读的章节展示原文，只需了解的章节原位显示摘要，可以跳过的章节原位折叠。用户持续向下阅读即可到达下一处重点，不需要返回顶部查找阅读建议。任何不确定情况都退回完整原文。**

---

## 1. 目标与结论先行

文章级阅读建议包含四种动作：`ignore`（可以忽略）、`summary_enough`（摘要即可）、`selective_read`（选择性阅读）、`deep_read`（全文精读）。

`selective_read` 的产品承诺是：

> **帮助用户直接找到值得亲自阅读的部分，并用摘要或跳过建议降低其余部分的阅读投入。**

当前实现虽然生成了章节级 `reading_plan`，但阅读计划与原始 Markdown 没有可靠关联。用户仍需自己在全文中寻找章节，无法真正节省注意力。

本方案不再把顶部阅读计划作为主要操作入口，而是直接把计划落实到正文顺序中：

```text
文章导语
↓
跳过章节：标题 + 跳过原因，可展开
↓
浏览章节：章节摘要，可展开原文
↓
建议阅读章节：完整原文
↓
重点精读章节：完整原文 + 强调标记
```

顶部只保留文章级建议、章节动作数量和模式切换等总览信息。用户阅读完一个重点章节后继续向下滚动，下一处值得读的内容会自然出现。

## 2. 方案适用范围

本文中的“原文”特指：

- PageSift 提交并保存在 SignalLens 中的 Markdown 正文；
- SignalLens Web 详情页内的阅读视图。

本文不处理外部网站实时 DOM 上的高亮或跳转。实时网页可能发生结构变化，也需要插件注入与站点兼容，属于另一项能力。

第一版解析正文中的 H1～H3，并为每篇文章选择一个包含 2～10 个标题的主章节层级。该范围用于复用当前 `content_map` 的输出上限并控制模型输出规模，不是长期产品规则。没有合适层级时保留现有分析结果和完整正文，不强行启用引导阅读流。

## 3. 现状与关键缺口

| 层 | 当前事实 | 本方案需要补全 |
| --- | --- | --- |
| 文章级建议 | 已实现 `ignore / summary_enough / selective_read / deep_read` | 不改变四种动作的语义 |
| 内容分析 | `content_map` 保存章节标题与摘要，最多 10 项 | 对符合条件的文章覆盖全部主章节，并增加来源章节引用 |
| 个性化评估 | `reading_plan` 保存自由文本章节名、动作与原因，最多 8 项 | `selective_read` 时覆盖全部主章节，数量上限同步到 10 |
| Web 阅读计划 | 独立展示章节动作列表 | 将动作与原因放回原文章节，不再依赖列表跳转 |
| Markdown 正文 | 整篇渲染，没有章节身份 | 按来源章节顺序组合原文、摘要与折叠卡片 |
| 历史分析 | 已有结果没有章节引用 | 保持可读，退回现有列表模式 |
| 英文翻译 | 已实现原文与译文对照 | 第一版不做双栏同步折叠 |

当前 `reading_plan` 是稀疏的重点列表，无法支撑连续引导阅读：未规划章节会形成很长的全文间隔，用户仍需自己寻找下一处重点。

因此本方案改变 `selective_read` 下的章节计划语义：

> **只要文章符合引导阅读条件，`reading_plan` 就必须对全部主章节各给出一次动作。缺少任何章节动作时，不启用部分折叠，而是整篇退回完整原文。**

其他文章级建议不要求生成穷举章节计划。

## 4. 核心设计原则

1. **来源结构优先**：章节身份来自原始 Markdown，不由 LLM 创造；
2. **先定位，后分析**：系统在 Analyze 调用前生成章节引用；
3. **精确引用，不做猜测**：不使用包含匹配、相似标题或 LLM 行号回找章节；
4. **内容与个性化分离**：Analyze 生成客观章节摘要，Evaluate 决定用户阅读动作；
5. **原始顺序不变**：Web 按来源章节顺序渲染，不使用模型返回顺序重排文章；
6. **完整计划才启用**：`selective_read` 的每个主章节都必须有且只有一个动作；
7. **连续阅读优先**：摘要和折叠发生在原位置，用户不需要返回顶部寻找下一节；
8. **用户始终可逆**：每个折叠章节可展开，并提供一键恢复完整原文；
9. **快照不一致即降级**：分析结果不能应用到后来变化的正文；
10. **辅助能力不阻塞主分析**：引导流不可用时仍保留摘要、建议和完整正文。

## 5. 章节身份：在模型调用前建立

### 5.1 自适应主章节层级

第一版解析 H1～H3，但同一篇文章只选择其中一个层级作为独立阅读单元：

1. 文首 H1 如果与 PageSift 采集的文章标题在空白和标点归一化后完全一致，则视为文档标题，不参与候选计数；
2. 在剩余标题中从 H1 到 H3 由浅到深检查；
3. 遇到第一个至少包含 2 个标题的层级，将其视为主章节候选；
4. 候选层级包含 2～10 个标题时启用引导阅读流；
5. 候选层级超过 10 个标题时直接退回完整原文，不再改选更深层级，以免只覆盖文章的一部分；
6. H1～H3 都不足 2 个标题时退回完整原文。

优先选择较浅层级，是为了保留完整论证上下文并避免把文章切得过碎，而不是追求最细粒度。层级选择完全由系统完成，LLM 只能使用结果，不能自行改选章节层级。

例如：

- 文章有 1 个 H2、6 个 H3 → 选择 H3；
- 文章有 5 个 H2、12 个 H3 → 选择 H2；
- 文章有 12 个 H2 → 不启用引导阅读流，不能绕过 H2 改选部分 H3；
- 文章只有 1 个 H2 和 1 个 H3 → 不启用引导阅读流。

选定层级后，一个主章节从该标题开始，到下一个同级或更浅标题、或者文章结束为止。更深标题及其正文保留在所属主章节内部，不单独产生动作。

文章标题、首个主章节之前的导语，以及更浅层单一容器标题下不属于任何主章节的内容，作为上下文块始终完整展示。第一版不混用多个标题层级，也不建立父子章节动作树，从而避免同一段正文同时受到父级和子级动作控制。

### 5.2 系统生成章节清单

Worker 在调用 Analyze 前解析 Markdown，忽略 YAML frontmatter 和代码围栏中的伪标题，选择主章节层级并生成有序章节清单：

```json
{
  "primary_heading_level": 2,
  "sections": [
    {
      "section_ref": "sec-001",
      "level": 2,
      "title": "为什么需要选择性阅读",
      "order": 1,
      "start_line": 18,
      "end_line": 47
    }
  ]
}
```

其中：

- `primary_heading_level` 是本次正文选择的唯一主章节层级；
- `section_ref` 是当前正文快照内的章节引用，不承诺跨正文版本稳定；
- `start_line / end_line` 是基于当前 Markdown 的零起点、左闭右开行号范围，由系统解析器生成，不允许 LLM 输出或修改；
- 标题重名不影响定位，因为引用由实际出现顺序决定；
- 分析记录保存本次 Markdown 的 `source_hash`，确保章节引用只应用于同一正文快照。

章节清单属于系统元数据，不属于 AI 结论。详情 API 只在当前 Markdown 与分析 `source_hash` 一致时返回可用章节清单。

### 5.3 将来源引用传递给模型

Analyze 输入同时包含原始正文和系统章节清单。对于具有 2～10 个主章节的文章，`content_map` 必须按章节清单为每个主章节生成一条摘要，并复制对应 `section_ref`。为避免完整覆盖明显放大输出，每节摘要应控制在 160 个字符以内：

```json
{
  "section_ref": "sec-001",
  "title": "为什么需要选择性阅读",
  "summary": "本节说明文章级建议无法直接指导用户在原文中分配注意力。"
}
```

Evaluate 读取带引用的 `content_map`，其 `reading_plan` 同样使用已有引用：

```json
{
  "section_ref": "sec-001",
  "section": "为什么需要选择性阅读",
  "action": "deep_read",
  "reason": "这是理解方案产品价值的核心论证。"
}
```

当最终建议为 `selective_read` 时，Evaluate 必须为 `content_map` 中的每个 `section_ref` 各生成一条动作，不得遗漏、重复或增加来源之外的章节。`reading_plan` 的数量上限由 8 调整为 10，与第一版章节上限一致。

`title / section` 继续保留为显示文本和旧数据兼容字段，但 Web 关联只能使用 `section_ref`，不能使用标题文本猜测位置。Web 始终按照系统章节清单的 `order` 渲染，不能采用模型返回的条目顺序。

### 5.4 引用与完整性校验

每个模型阶段完成后，系统校验：

- `section_ref` 是否存在于当前章节清单；
- 是否出现重复引用；
- `reading_plan.section_ref` 是否存在于已验证的 `content_map`；
- `selective_read` 时 `content_map` 与 `reading_plan` 是否都完整覆盖章节清单；
- `selective_read` 是否同时至少包含一个 `skip / skim` 和一个 `read / deep_read`，避免与“摘要即可”或“全文精读”语义重叠；
- 当前正文哈希是否仍与分析快照一致。

单个无效条目不应使三阶段分析整体失败，但会使本次引导阅读流失去完整性。系统不得使用剩余条目进行部分折叠，也不得伪造新引用或模糊匹配标题；页面应保留文章级建议、摘要和现有阅读计划说明，并将正文整体退回完整原文模式。

## 6. Web 呈现：顺序式引导阅读流

### 6.1 启用条件

只有同时满足以下条件，详情页才启用引导阅读流：

- AI 原始建议为 `selective_read`；
- 系统从 H1～H3 中选出了包含 2～10 个标题的单一主章节层级；
- `content_map` 和 `reading_plan` 都完整且唯一地覆盖全部主章节；
- 所有 `section_ref` 均通过校验；
- 章节动作同时包含需要压缩和需要阅读的章节；
- 当前 Markdown 与分析 `source_hash` 一致；
- 用户没有把本次建议修正为其他文章级动作。

如果用户把其他建议修正为 `selective_read`，现有反馈只改变文章级判断，不会凭空生成完整章节计划；在重新分析前仍展示完整原文。

### 6.2 正文就是阅读计划

顶部不再展示需要反复返回操作的章节跳转列表，只显示简短总览，例如：

```text
选择性阅读
2 节重点精读 · 1 节建议阅读 · 3 节浏览摘要 · 2 节跳过
[引导阅读] [完整原文]
```

正文区域按照系统章节清单的原始顺序依次渲染：

1. 文章标题、导语和主章节之外的上下文块完整展示；
2. 每个主章节在原位置读取对应的章节摘要、动作和原因；
3. `skip / skim` 在原位置压缩，`read / deep_read` 在原位置展示原文；
4. 用户读完当前重点章节后继续向下滚动，下一处重点自然出现在后续正文中；
5. 页面不要求用户返回顶部，也不把“跳转到下一节”作为完成阅读的必要操作。

阅读计划的原因和动作直接显示在对应章节中。独立计划列表不再作为新分析结果的主要呈现；历史分析由于没有可靠章节引用，仍可保留原有列表展示。

### 6.3 四种章节动作

| 动作 | 原位呈现 | 用户可执行操作 |
| --- | --- | --- |
| `skip` | 显示章节标题、跳过徽章和跳过原因，不显示摘要 | 展开本节原文 |
| `skim` | 显示章节标题、浏览徽章和章节摘要 | 展开本节原文 |
| `read` | 完整显示章节原文，并标记“建议阅读” | 正常连续阅读 |
| `deep_read` | 完整显示章节原文，并使用更强的“重点精读”标记 | 正常连续阅读 |

额外约束：

- 每个 `skip / skim` 章节都可在原位置展开，不打开新页面；
- `skim` 缺少同引用章节摘要时，整条引导阅读流降级为完整原文；
- 单个章节展开后保持用户本次页面会话中的选择；
- 连续多个 `skip / skim` 章节仍按原顺序分别显示，不能合并后丢失章节边界；
- Web 只按来源章节清单排序，不能按重要性重新排列原文；
- 折叠只改变呈现，不删除或截断保存的 Markdown。

### 6.4 完整原文模式

满足启用条件时默认显示引导阅读流，同时在正文顶部持续提供“完整原文”切换：

- 切换后立即展开全部章节；
- 切回引导阅读时恢复本次页面会话中的手动展开状态；
- 模式切换不修改 AI 结果、用户反馈或保存的 Markdown；
- 引用、覆盖范围或正文哈希任一校验失败时，只提供完整原文，不展示部分引导流。

顶部总览只用于说明 AI 如何分配章节动作，不承担目录导航职责。第一版不提供顶部章节点击跳转。

### 6.5 翻译视图

第一版引导阅读流只作用于单栏原文阅读视图。进入中英对照时，两栏均展示完整内容，不尝试按译文标题重新匹配，也不做双栏同步折叠。

后续若需要支持译文引导，应沿用来源 `section_ref` 和翻译块顺序建立对应关系，不能拿翻译后的标题进行文本匹配。

## 7. 历史数据与正文变化

- 历史 `content_map` / `reading_plan` 没有 `section_ref`，API 必须继续允许读取；
- 历史结果只展示现有阅读计划列表和完整正文，不启用引导阅读流；
- 新字段在读取旧分析时允许为空，新 Worker 结果则执行严格引用校验；
- 重复采集可能更新同一内容记录的 Markdown；如果正文哈希改变，旧章节计划立即停止作用于原文；
- 本方案不顺带改变重复采集或自动重分析策略，只保证旧计划不会错误标记新正文。

## 8. 边界与不做的事

- 不在外部网站实时页面中高亮；
- 不做段落级、句子级标注；
- 不混用 H1～H3 多个层级，也不建立嵌套章节动作树；
- 不实现顶部章节点击跳转；
- 不在章节计划不完整时启用部分引导流；
- 不使用标题包含匹配、语义相似度或向量检索定位章节；
- 不让 LLM 生成行号、字符偏移或 DOM Selector；
- 不引入向量库、新服务或新的模型调用阶段；
- 不把该交互扩散到 `summary_enough`、`deep_read` 或 `ignore`；
- 不因章节引导失败而生成占位 AI 结论或隐藏原文。

## 9. 与 SignalLens 现有原则的兼容性

- **Analyze 不读取完整画像**：章节结构和摘要仍属于内容本体分析；
- **Evaluate 才决定个性化动作**：同一章节可因用户知识与目标不同得到不同阅读建议；
- **手动提交不静默过滤**：折叠可逆，完整原文始终可恢复；
- **不确定时保守展示**：无引用、引用异常、快照变化时都展示完整正文；
- **保留原文真实分歧**：系统不删除章节，用户可检查摘要是否遗漏限制、反方观点或未验证主张；
- **精准修改产品边界**：本能力只补全阅读分诊到实际消费之间的断点，不扩展成批注或知识库系统。

## 10. 验证标准

### 10.1 结构与关联正确性

- YAML frontmatter 和代码围栏中的 `#` 不产生错误章节；
- 文首 H1 只有与采集标题归一化后完全一致时才从候选中排除；
- 单一 H2 下存在多个 H3 时可以选择 H3，多个 H2 下存在更多 H3 时仍优先选择 H2；
- 首个至少包含 2 个标题的层级超过 10 项时直接降级，不改选更深层级；
- 更深标题保留在所属主章节内部，不会得到第二套阅读动作；
- 同一主层级的重名标题得到不同 `section_ref`，且均能精确定位；
- 合法引用全部定位到原本章节，不接受“相似但错误”的定位；
- `selective_read` 的 `content_map` 与 `reading_plan` 分别完整覆盖全部主章节；
- `selective_read` 同时包含需要压缩和需要阅读的章节，否则返回与动作分布一致的其他文章级建议；
- 未知、重复或缺失引用使整条引导流降级，但不导致分析任务或详情页报错；
- H1～H3 没有合适主层级，或首个有效候选层级超过 10 个标题时，稳定退回完整原文；
- 正文哈希变化后不再应用旧章节标记；
- 旧分析 JSON 无需重跑即可正常读取。

第一版不预设“命中率 ≥ 90%”这类缺乏基线的数字。由于章节引用在模型调用前生成，系统定位本身应当是确定性的；需要单独记录的是模型返回合法引用的比例，以及文章因结构不足而降级的比例。

### 10.2 交互正确性

- 满足条件的 `selective_read` 默认显示顺序式引导阅读流；
- 章节始终保持原文顺序，模型输出顺序不会改变正文排列；
- `skip / skim / read / deep_read` 在各自原位置按约定呈现；
- 用户持续向下滚动即可从当前重点到达下一处重点，不需要返回顶部阅读计划；
- 顶部总览不承担章节目录或必需跳转操作；
- 每个折叠章节和整篇文章都能恢复完整原文；
- `summary_enough / deep_read / ignore` 不显示引导阅读入口；
- 用户修正文章级建议后，不继续自动应用与修正结果冲突的旧计划；
- 中英对照视图保持完整内容，不发生原文与译文章节错配。

### 10.3 产品有效性

使用一组真实文章进行人工对照，至少分别判断：

- `read / deep_read` 是否覆盖文章的关键证据、新知识与必要上下文；
- `skip / skim` 是否错误隐藏理解后文所必需的内容；
- 章节摘要是否忠实保留限制、分歧和不确定性；
- 用户是否比直接扫全文更快找到值得阅读的部分；
- 用户能否在不返回顶部的情况下连续完成建议阅读路径；
- 用户手动展开被折叠章节的原因是正常探索，还是 AI 动作判断错误。

锚点正确只证明功能可以使用；是否形成连续阅读、节省时间且没有遗漏重要内容，才决定引导阅读流是否有效，以及后续是否继续默认开启。

## 11. 建议开发顺序

1. **评测样本**：准备以 H1、H2、H3 为主层级、层级混合、重名标题、代码围栏标题、章节过多和正文更新样本；验证：明确每篇文章预期主层级与章节边界；
2. **来源章节解析**：选择单一主层级并生成快照内 `section_ref`、位置与 `source_hash`；验证：主层级选择和解析器测试全部通过；
3. **内容地图契约**：让符合条件的文章为全部主章节生成带引用摘要；验证：覆盖范围、顺序和未知引用用例通过；
4. **完整章节计划**：`selective_read` 时为全部主章节生成唯一动作，并兼容旧结果；验证：缺失、重复和旧 JSON 用例通过；
5. **顺序式引导阅读流**：按来源顺序组合折叠卡片、摘要和原文；验证：用户持续向下即可依次阅读所有重点；
6. **完整原文与降级**：增加整体切换、单节展开、快照校验和翻译视图边界；验证：任何异常状态下都能恢复全文；
7. **真实文章评测**：记录合法引用率、结构降级率、错误折叠与实际节省时间，并人工观察用户是否仍需返回顶部；验证：确认连续阅读路径是否有效。

章节解析、完整计划和顺序式正文流可以按层实现，但不能把“顶部计划点击跳转”作为独立产品阶段上线。没有完整计划时，最安全且语义一致的结果仍是摘要、文章级建议和完整原文。
